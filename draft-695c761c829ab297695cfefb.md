## Hping3

Hping3 is a network tool that allow TCP, UDP, and ICMP packet manipulation. Pentesters and network engineer use it for varity of purpose like to test firewall rules, post scanning, audit TCP/IP stacks etc.

We’ll hping3 to overwhlem router’s processing capaciry or memory by flooding it with spefically crafted packets. Such types of attacks vary of type of router for instance if we keep flodding the router for 2-5 mins it can cause freeze, reboot, or become unresponsive which all leads to disconnecting users from the wifi. hping3 is excellent for this because it allows you to control the packet type, source address, size, and speed with high precision.

### Method 1: SYN Flood (Most Common)

```bash
sudo hping3 --flood -S -p 80 -d 120 <TARGET_IP>
```

* **sudo**: You need root/administrator privileges to send raw packets. It is must for tools like nmap as well.
    
* **\--flood**: Send packets as fast as possible, without waiting for replies.
    
* **\-S & -p**: Send TCP `SYN` packets to the target on port 80 (it could be any open port most commom: 53, 80, 443).
    
* **\-d**: sent packet size to 120 bytes.
    
* **&lt;TARGET\_IP&gt;**: The IP address of your target router (e.g., 192.168.1.1).

### Q1: Which attack is more effective TCP or UDP?

Answer is simple, which is a more complicated protocol, TCP of course. Our goal is to overwhlem the router’s processing capacity. TCP requires router to mantian a connection and every SYN packet initiate by us router will reply with ASK to complete a three-way handshack. Each fake SYN makes the server allocate resources (SYN backlog).

If the backlog fills, the server stops accepting new connections.

This can take down web servers, SSH, databases, etc., even at moderate packet rates.

UDP flood: more dangerous to the network bandwidth. No connection state, so servers don’t track it the same way.

Damage comes from sheer bandwidth.If your goal is to clog the pipe, UDP flood is more dangerous.
